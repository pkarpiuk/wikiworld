Wikidumptools

Narzędzie do ściągania i przetwarzania dumpów projektów Wikimedia

1. Wprowadzenie

Wikidumptools to skonteneryzowane narzędzie, które zaciąga dumpy wybranych wersji językowych Wikipedii oraz dane statystyczne o wejściach użytkowników Wikipedii na artykuły hasłowe (tzw. pageviews: miesięczne, dobowe, godzinowe) oraz o historii przechodzenia użytkowników pomiędzy artykułami (tzw. clickstream). Narzędzie chodzi w pętli, automatycznie dociąga najnowsze wersje dumpów, pozwala na przełączanie się między wersjami dumpów (ustalenie która wersja jest aktualna na użytek innych aplikacji które z takiego dumpa korzystają) i usuwa niepotrzebne (stare) wersje żeby nie zużywać za dużo przestrzeni dyskowej.

Dane są zasadniczo zrzucane w formacie TSV i JSON, w odróżnieniu od SQL i XML preferowanego przez twórców Wikipedii.

Ponadto wikidumptools na kilka sposobów przetwarza zaciągnięte dane i generuje pewną wartość dodaną, np. obraz mapy świata pokazujący jakimi miejscami na świecie zainteresowani są użytkownicy danej wersji językowej Wikipedii w ostatnim roku, oraz informacje o 1000 najpopularniejszych artykułach w ciągu ostatnich 1,3,6,12,24 godzin dla każdej wersji językowej Wikipedii.

2. Uruchamianie

git clone https://github.com/pkarpiuk/wikiworld.git
cd wikiworld/docker/wikidumptools
docker build --no-cache=true -t wikidumptools .
export DATA_DIR=/mnt/arch/wiki-data
docker run --restart=unless-stopped --rm -v ${DATA_DIR}:/db -e WIKIPEDIA_LANGUAGES='pl en' wikidumptools daily
docker run --restart=unless-stopped --rm -v ${DATA_DIR}:/db wikidumptools hourly
docker run --restart=unless-stopped --rm -v ${DATA_DIR}:/db wikidumptools rest
docker run --restart=unless-stopped --rm -v ${DATA_DIR}:/db -e EVENTS_DAYS=64 wikidumptools events

Uwaga: Nigdy nie należy uruchamiać więcej niż jednej instancji narzędzia z tymi samymi parametrami (np. dwóch instancji 'wikidumps daily'). Efektem będzie kaszanka w systemie plików, potencjalnie nieodwracalna.

3. Zmienne środowiskowe

Musi być zdefiniowana i niepusta przynajmniej jedna z dwóch zmiennych: WIKIPEDIA_LANGUAGES lub WIKIQUOTE_LANGUAGES.

WIKIPEDIA_LANGUAGES
(daily) Lista rozdzielonych spacją wersji językowych Wikipedii, które mają być ściągane, np. 'pl en de'.
WIKIQUOTE_LANGUAGES
(daily) Lista rozdzielonych spacją wersji językowych Wikicytatów, które mają być ściągane, np. 'pl en de'
PAGEVIEW_MONTHS
(daily) Ile ostatnich plików miesięcznych pageview ściągnąć. Domyślnie 26, 0 oznacza wszystkie, <0 oznacza nie ściągać w ogóle
PAGEVIEW_DAYS
(daily) Ile ostatnich plików dziennych pageview ściągnąć. Domyślnie 64, 0 oznacza wszystkie, <0 oznacza nie ściągać w ogóle
CLICKSTREAM_MONTHS
(daily) Ile ostatnich plików miesięcznych clickstream ściągnąć. Domyślnie 0 (czyli wszystkie), <0 oznacza nie ściągać w ogóle
EVENTS_DAYS
(events) Z ilu ostatnich dni przechowywać zdarzenia modyfikacji/tworzenia artykułów. Domyślnie 64, 0 oznacza wszystkie

4. Ukryte zmienne

SupportedWikiLangs to lista wersji językowych Wikipedii dla których narzędzie Wikidumptools ma najlepsze wsparcie. Są to wersje:

  • de (niemiecka)
  • en (angielska)
  • es (hiszpańska)
  • fr (francuska)
  • it (włoska)
  • ja (japońska)
  • pl (polska)
  • pt (portugalska)
  • ru (rosyjska)
  • zh (chińska)

Zmienna ta ma znaczenie w przypadku clickstream i hours-pageview.

6.2. hour-pageview.json

Pliki DATA_DIR/public/wikipedia/lang/version/hour-pageview.json są generowane średnio co godzinę dla każdej wersji językowej Wikipedii wymienionej w zmiennej środowiskowej WIKIPEDIA_LANGUAGES oraz SupportedWikiLangs. Każdy taki plik zawiera informacje o ok. 1000 najpopularniejszych artykułach w ostatnich max. 24 godzinach.

W poniższym opisie nazwa pola ujęta w nawiasy kwadratowe oznacza że pole jest opcjonalne.

ts_utc
na jaką godzinę aktualny jest plik (w formacie YYYY-MM-DD HH:00:00)
articles
page_id
(long) identyfikator artykułu hasłowego
title
(string) tytuł artykułu (znaki spacji zamienione na podkreślenia)
views
(list of int) lista 6 wartości liczbowych, które mówią ile było wejść do bieżącego artykułu w ciągu 1, 3, 6, 12, 24 ostatnich godzin oraz w ciągu ostatniego roku
[gps]

Dokładne znaczenie pól primary, globe, dim, type, name i country na stronie https://www.mediawiki.org/wiki/Extension:GeoData. Tylko 3 pierwsze pola są sensownie wypełniane w każdej wersji językowej Wikipedii. Polska wersja językowa ma pozostałe pola wypełnione nierzetelnie (np. dim) lub wcale (w 99% przypadków).

lat
(float) szerokość geograficzna
lon
(float) długość geograficzna
primary
(bool) true gdy współrzędne odnoszą się do samego artykułu; false gdy są to współrzędne jakiegoś miejsca wspomnianego w artykule (np. artykuł jest o Marii Konopnickiej a miejsce jej urodzenia ma współrzędne GPS)
[globe]
(string) earth dla Ziemi
[dim]
szacowana wielkość obiektu (w metrach)
[type]
rodzaj obiektu
[name]
nazwa obiektu
[country]
kod państwa w którym obiekt występuje
length
(int) długość artykułu (w bajtach)
[langlinks]
mapa z kodu wersji językowej Wikipedii (string) w tytuł artykułu (lub przekierowania) w tej wersji językowej (string, znaki spacji NIE są zamieniane na podkreślenia).
[image_file]
(string) nazwa pliku głównego obrazka artykułu
[cats]
(list of long) lista identyfikatorów kategorii
[pagelinks]
(list of string) lista identyfikatorów artykułów do których można przejść z bieżącego artykułu po linkach
[templates]
(list of string) lista nazw szablonów (namespace 10) użytych w artykule (spacje zamienione na znaki podkreślenia), np. infoboksy
[prev]
(map: string to int) skąd użytkownicy przeszli do artykułu; max. 20 pozycji
  • klucz: pid: identyfikator artykułu źródłowego lub łańcuch other-* (patrz opis w https://meta.wikimedia.org/wiki/Research:Wikipedia_clickstream#Data_Preparation)
  • wartość: count: liczba wejść z danego artykułu docelowego (zawsze >= 10)
[next]
(map: string to int) dokąd użytkownicy poszli z artykułu; max. 20 pozycji
  • klucz: pid: identyfikator artykułu docelowego
  • wartość: count: liczba wyjść do danego artykułu docelowego (zawsze >= 10)
categories
(list of map) lista kategorii grafu kategorii zawierającego wszystkie artykuły wymienione w pliku; kolejność kategorii jest w kolejności obchodzenia grafu w głąb począwszy od korzenia. Uwaga: graf jest uproszczony, tzn. poprzez kontrakcję usunięto wierzchołki które nie mają langlinków do wszystkich języków wymienionych w SupportedWikiLangs. Dzięki temu np. dla angielskiej Wikipedii liczba kategorii redukuje się z ok. 100 tys. do ok. 7 tys.
Pola pojedynczej kategorii:
  • id: identyfikator kategorii,
  • title: tytuł kategorii (spacje zamienione na znaki podkreślenia)
  • parents: lista identyfikatorów rodziców kategorii (pusta w przypadku korzenia)
  • children: lista identyfikatorów dzieci kategorii (pusta w przypadku liścia)
  • wikidata_id: identyfikator kategorii w WikiData
  • is_meta: true gdy to jest metakategoria, brak pola w przeciwnym przypadku
  • articles_count: liczba artykułów w tej kategorii (ale nie podkategoriach), brak pola gdy 0
  • subtree_articles_count: liczba artykułów w całym poddrzewie kategorii, włącznie z bieżącą
  • subtree_cats_count: liczba kategorii w całym poddrzewie (włącznie z bieżącą kategorią, a więc będzie zawsze co najmniej 1)
  • langlinks: mapa par w rodzaju "Category:18th-century people" zawierających linki do odpowiedników bieżącej kategorii w innych wersjach językowych Wikipedii

Logi z generowania plików hour-pageview.json są składowane w DATA_DIR/logs/hours-pageview-logs.txt (ten plik jest nadpisywany co godzinę).

6.3. geo-by-*.png

W katalogu DATA_DIR/public/wikipedia/lang/version generowane są obrazy geo-by-*.png. Każdy z nich ma rozdzielczość 2400x1211 i czarne tło, a przedstawia mapę świata z białymi kropkami reprezentującymi artykuły Wikipedii. Jasność kropek odzwierciedla:

geo_by_pagecount.png

geo_by_pagelen.png
łączną długość artykułów (w znakach) w okolicy
geo_by_pageviews.png
łączną popularność artykułów w ostatnim roku w okolicy

Logi z tego procesu są składowane w DATA_DIR/cache/dumps/wikipedia/lang/version/geomap-logs.txt.

7. Clickstream

Pliki clickstream udostępniane w https://dumps.wikimedia.org/other/clickstream i opisane w https://meta.wikimedia.org/wiki/Research:Wikipedia_clickstream. Są one generowane od 2017-11 co miesiąc tylko dla niektórych wersji językowych Wikipedii (SupportedWikiLangs).

Pliki clickstream clickstream-langwiki-YYYY-MM.tsv.gz (domyślnie wszystkie) są zrzucane do DATA_DIR/cache/clickstream/YYYY-MM. Są one obecnie wykorzystywane do generowania plików clickstream-articles.json.gz oraz hour-pageview.json dla każdej wersji językowej Wikipedii.

Logi ze ściągania tych plików są przechowywane w DATA_DIR/logs/clickstream-logs.txt.

8. Katalogi pageview

Pliki pageview mają po jednym rekordzie w wierszu, wiersz ma postać (dokładny opis - https://dumps.wikimedia.org/other/pagecounts-ez/):

  1. kod językowy projektu (np. polska wikipedia to będzie 'pl.z')
  2. tytuł artykułu (znaki spacji zamienione na podkreślenia)
  3. liczba odwiedzin w danym przedziale czasu (np. miesiąca dla pageview miesięcznych)

Plik pageview obejmuje wejścia na wszystkie projekty Wikimedia i wszystkie wersje językowe (nie tylko Wikipedie, ale też Wikiquote, Wikibooks itp.).

pl.z Rzeczpospolita_Polska 4596

8.1. Miesięczne

W katalogu DATA_DIR/cache/pageview/months przechowywane są pliki pagecounts-YYYY-MM-views-ge-5-totals.bz2 ściągane z https://dumps.wikimedia.org/other/pagecounts-ez/merged/.

W pliku tego typu przechowywane są liczby odwiedzin każdego artykułu każdej wersji językowej każdego projektu Wikimedia z granulacją miesięczną. Domyślnie system utrzymuje ostatnich 26 plików (miesięcy), potrzebnych jest minimum 12 - patrz zmienna środowiskowa PAGEVIEW_MONTHS. Najstarsze pliki są usuwane, żeby nie zajmowały miejsca.

Pliki pageview miesięczne są wykorzystywane do generowania pliku months_pageview_articles.tsv.gz dla każdej wersji językowej Wikipedii.

Logi ze ściągania tych plików są przechowywane w DATA_DIR/logs/pageview-months-logs.txt.

8.2. Dobowe

W katalogu DATA_DIR/cache/pageview/days przechowywane są pliki pagecounts-YYYY-MM-DD.bz2 ściągane z https://dumps.wikimedia.org/other/pagecounts-ez/merged/YYYY/YYYY-MM.

W pliku tego typu przechowywane są liczby odwiedzin każdego artykułu każdej wersji językowej każdego projektu Wikimedia z granulacją dobową. Domyślnie system utrzymuje ostatnich 64 plików (dni), potrzebnych jest minimum 31 - patrz zmienna środowiskowa PAGEVIEW_MONTHS. Najstarsze pliki są usuwane, żeby nie zajmowały miejsca.

Pliki pageview dobowe obecnie nie są wykorzystywane do generowania żadnych plików pochodnych.

Logi ze ściągania tych plików są przechowywane w DATA_DIR/logs/pageview-days-logs.txt.

8.3. Godzinowe

W katalogu DATA_DIR/cache/pageview/hours przechowywane są pliki pageviews-YYYYMMDD-HH0000.gz ściągane z https://dumps.wikimedia.org/other/pageviews/YYYY/YYYY-MM.

W pliku tego typu przechowywane są liczby odwiedzin każdego artykułu każdej wersji językowej tylko wybranych wersji językowych Wikipedii (SupportedWikiLangs), z granulacją godzinną. Domyślnie system utrzymuje ostatnich 24 plików (godzin), potrzebnych jest minimum 24. Najstarsze pliki są usuwane, żeby nie zajmowały miejsca.

Pliki pageview godzinowe są wykorzystywane do generowania pliku DATA_DIR/public/wikipedia/lang/version/hour-pageview.json.

Logi z procesu ściągania tych plików są składowane w DATA_DIR/logs/hours-pageview-logs.txt (ten plik jest nadpisywany co godzinę).

9. Katalog dumpa

Tutaj trafiają przetworzone pliki danej wersji językowej Wikipedii, np. dla polskiej wersji z https://dumps.wikimedia.org/plwiki/

Dla każdej wersji językowej Wikipedii wymienionej w zmiennej środowiskowej WIKIPEDIA_LANGUAGES tworzony jest katalog DATA_DIR/cache/dumps/wikipedia/lang, a w nim katalogi YYYYMMDD z wersjami przetworzonych dumpów danej wersji językowej Wikipedii, np. $DATA_DIR/cache/dumps/wikipedia/pl/20191220 oraz linki symboliczne current i (opcjonalnie) previous.

Idea jest taka, że link symboliczny current wskazuje aktualnie używaną wersję dumpa, a previous poprzednio używaną (tak by można było się łatwo do niej cofnąć gdyby się okazało że bieżąca nie spełnia oczekiwań). Wywołanie 'wikidumptools daily' systematycznie sprawdza czy w https://dumps.wikimedia.org/lang/ pojawiła się nowa wersja dumpa i jeśli tak, to dociąga ją do odpowiedniego nowego katalogu YYYYMMDD. Zasadniczo w dłuższej perspektywie dla każdej wersji językowej Wikipedii będą przechowywane maksymalnie 4 wersje dumpów:

  • najnowszy (ang. latest),
  • najnowszy poprawny (ang. latest valid),
  • bieżący (current),
  • poprzedni (previous).

Może ich być mniej, ponieważ np. najnowszy, najnowszy poprawny i bieżący mogą być tożsame, a poprzedni może nie istnieć (tak jest zwykle po pierwszym cyklu działania polecenia 'wikidumptools daily'). Wersji dumpa nie powinno być więcej niż 4, ponieważ wszystkie pozostałe wersje są automatycznie usuwane.

Polecenie

docker run --rm -v ${DATA_DIR}:/db -e WIKIPEDIA_LANGUAGES='pl en' wikidumptools switch version options

przełącza linki symboliczne current i previous stosownie do zaaplikowanych parametrów.

Uwaga: przed uruchomieniem tego polecenia należy zatrzymać (docker stop) wszystkie inne wywołania narzędzia wikidumptools.

Uwaga: na analogiczne wersje przepinany jest link symboliczny current w odpowiednim katalogu DATA_DIR/public/wikipedia/lang.

Parametr version określa jaki zakres będzie miało przełączenie:

  • lang (np. plwiki, enwiki itp.) - wskazana wersja językowa,
  • wiki - wszystkie wersje językowe Wikipedii,
  • wikiquote - wszystkie wersje językowe Wikiquote,
  • ALL - wszystkie wersje językowej Wikipedii i Wikiquote.

Parametr options określa na jaką wersję dumpa ma zostać przepięty link symboliczny current:

  • latest_valid na najnowszy poprawny,
  • latest na najnowszy (niekoniecznie poprawny),
  • previous na poprzedni (rollback),
  • YYYYMMDD na konkretną wskazaną wersję dumpa

Jeśli dla danego dumpa przepięcie się uda, to link symboliczny previous będzie wskazywał na poprzedni cel linku symbolicznego current.

9.1. Pliki pierwotne

Artykuły (namespace 0), przekierowania (też namespace 0) i kategorie (namespace 14) mają wspólną przestrzeń identyfikatorów, tzn. np. nie może być artykułu o tym samym identyfikatorze co kategoria. Tytuły (artykułów, przekierowań, kategorii) zwykle są z dużej litery, spacje zamienione na znak podkreślenia (o ile nie wskazano inaczej). Wartości NULL są reprezentowane przez łańcuch pusty.

abstracts.tsv.gz

Jednozdaniowe skróty artykułów. Często niestety śmieci zawierające znaki takie jak '|={}[]'.

categories.json.gz

Na każdą kategorię przypada jeden wiersz - rekord JSON. Poszczególne pola rekordu oznaczają:

  • id: identyfikator kategorii,
  • title: tytuł kategorii (spacje zamienione na znaki podkreślenia)
  • parents: lista identyfikatorów rodziców kategorii (pusta w przypadku korzenia)
  • children: lista identyfikatorów dzieci kategorii (pusta w przypadku liścia)
  • wikidata_id: identyfikator kategorii w WikiData
  • is_meta: true gdy to jest metakategoria, brak pola w przeciwnym przypadku
  • articles_count: liczba artykułów w tej kategorii (ale nie podkategoriach), brak pola gdy 0
  • subtree_articles_count: liczba artykułów w całym poddrzewie kategorii, włącznie z bieżącą
  • subtree_cats_count: liczba kategorii w całym poddrzewie (włącznie z bieżącą kategorią, a więc będzie zawsze co najmniej 1)

Przykład:

{"id":3239599,"title":"Nieistniejące_kluby_sportowe_w_Stanach_Zjednoczonych","parents":[2198034,2197915],
"children":[1026467,3239602], "wikidata_id":"Q8371215","articles_count":2,"subtree_articles_count":227,"subtree_cats_count":21}
clickstream-articles.json.gz
  • _id: identyfikator artykułu
  • prev: skąd użytkownicy przeszli do artykułu
    • pid: identyfikator artykułu źródłowego lub jeden z identyfikatorów other-* (patrz opis). Identyfikator other-search oznacza że artykuł najprawdopodobniej został znaleziony w wyszukiwarce Wikipedii
    • count: liczba wejść z danego źródła (zawsze >= 10)
  • next: do jakiego artykułu użytkownicy przeszli
    • pid: identyfikator artykułu docelowego
    • count: liczba wyjść do danego artykułu docelowego (zawsze >= 10)

W polach prev i next uwzględniono max. 20 przejść o największym wolumenie (pozostałe odrzucono).

Przykład:

{
  "_id":3672369,
  "prev":{"86107":1157,"other-empty":226,"other-search":759,"other-search-internal":79},
  "next":{"108287":78,"38195":13,"86077":10}
}

10. DB

W katalogu DATA_DIR/db przechowywane są takie dane, które trudno odtworzyć, więc zasadniczo nie powinno się tego katalogu usuwać, a przy przenoszeniu całej infrastruktury na inną maszynę warto go spakować i odtworzyć na nowej lokalizacji.

10.1. Rest

W udostępnianych publicznie plikach dumpów pewne ciekawe dane są trudno dostępne lub wręcz niedostępne. Dla każdej wersji językowej Wikipedii w pliku DATA_DIR/db/wikipedia/articles/lang.json przechowujemy ściągnięte przez API Wikipedii rekordy o poszczególnych artykułach:

  • page_id: (int) identyfikator artykułu
  • download_ts: (string) data utworzenia rekordu (ściągnięcia danych z Internetu), w formacie. "2020-01-17T15:36:42+01:00"
  • create_ts: (string) data utworzenia pierwszej rewizji artykułu, w formacie. "2002-07-27T00:34:39Z" (Wikipedia API DOC)
  • summary: (JSON) wynik ściągnięty z https://lang.wikipedia.org/api/rest_v1/page/summary/tytuł_artykułu (Wikipedia API DOC)
  • media: (JSON) wynik ściągnięty z https://lang.wikipedia.org/api/rest_v1/page/media/tytuł_artykułu (Wikipedia API DOC)
  • related: (JSON) wynik ściągnięty z https://lang.wikipedia.org/api/rest_v1/page/related/tytuł_artykułu (Wikipedia API DOC)

Narzędzie 'wikidumptools rest' chodzi w kółko i uzupełnia pliki. Dba żeby dane były zawsze aktualne (np. o obrazkach), można założyć że podmiana pliku odbywa się w sposób atomowy. 10.2. Events

Polecenie 'wikidumptools events' subskrybuje strumień zmian (i tworzenia nowych) artykułów w projektach Wikimedia Foundation (a więc we wszystkich wersjach językowych Wikipedii, Wikiquote, WikiNews, Wikidata, itp.) dokonanych przez użytkowników (a więc nie przez boty) i metadane o tych zmianach zapisuje w plikach DATA_DIR/db/events/raw/YYYY-MM-DD.json. Trzymane są pliki z ostatnich EVENTS_DAYS dni (domyślnie 64).

Obserwowany strumień nosi nazwę recentchange. Inne potencjalnie interesujące strumienie (ale nie obsługiwane przez narzędzie wikidumptools) są opisane tu.

Struktura generowanych przez Wikimedia Foundation zdarzeń opisana jest tu.

W plikach trzymane są tylko zdarzenia, które spełniają wszystkie poniższe warunki naraz:

  • pole type ma wartość 'new' lub 'edit'
  • pole namespace ma wartość 0
  • pole bot ma wartość 0.

Aby dodatkowo zredukować ilość zajmowanego na dysku miejsca, rekordy w plikach ograniczone są do pól:

  • type: 'new' lub 'edit'
  • wiki: nazwa projektu, np. 'plwiki', 'wikidatawiki', 'enwiktionary' itp.
  • title: tytuł artykułu
  • [comment]: opcjonalny komentarz modyfikacji
  • timestamp: data zdarzenia (UNIX)
  • user: nazwa użytkownika dokonującego zmiany
  • [minor]: true gdy jest to drobna zmiana, brak pola gdy false
  • [patrolled]: true gdy zmiana jest patrolowana, brak pola gdy false
  • length: jak zmieniła się długość (w bajtach) artykułu po modyfikacji: 
    { new: val-new, old: val-old }
    Wartość val-old może wynosić -1 gdy utworzono pierwszą wersję artykułu
  • revisions: numer starej i nowej rewizji artykułu, format danych taki sam jak w poprzednim polu

Przykład:

{
  "type": "edit",
  "wiki": "plwiki",
  "title": "Mandaryna",
  "comment": "Poprawienie nieprawdziwej informacji - uczyła się śpiewu, ale nie u p. Zapendowskiej",
  "timestamp": 1579268095,
  "user": "37.7.187.10",
  "minor": true,
  "patrolled": true,
  "length": { "old": 28072, "new": 28029 },
  "revision": { "old": 58549400, "new": 58551390 }
}
